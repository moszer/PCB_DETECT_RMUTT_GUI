# บทที่ 4
# ผลการดำเนินงานและการวิเคราะห์

การดำเนินโครงงาน "ระบบตรวจสอบความสมบูรณ์ของแผ่น PCB ด้วยปัญญาประดิษฐ์" ได้ดำเนินการพัฒนาและทดสอบระบบอย่างเป็นลำดับขั้นตอน โดยครอบคลุมตั้งแต่การฝึกสอนโมเดลปัญญาประดิษฐ์ การประเมินประสิทธิภาพของโมเดล การพัฒนาระบบตรวจสอบเชิงพิกัดด้วยอัลกอริทึม Greedy Nearest-Neighbor Matching การทดสอบผ่านโปรแกรมส่วนต่อประสานผู้ใช้ทั้งรูปแบบ Desktop Application (PyQt6) และ Web-based AOI System (Next.js + FastAPI) ตลอดจนการทดสอบการใช้งานระบบแสงสว่างแบบโดมกระจายแสง (Diffuse Dome Light) โดยสามารถจำแนกและวิเคราะห์ผลการดำเนินงานออกเป็นหัวข้อสำคัญดังต่อไปนี้

## 4.1 ลักษณะภาพถ่ายและชุดข้อมูลชิ้นส่วนอุปกรณ์อิเล็กทรอนิกส์

ในการตรวจหาความผิดปกติและความสมบูรณ์ของแผ่นวงจรพิมพ์ ระบบจำเป็นต้องสามารถตรวจจับและจำแนกชนิดของชิ้นส่วนอิเล็กทรอนิกส์ได้อย่างครอบคลุม ทั้งชิ้นส่วนชนิดเจาะรูผ่านแผ่น (Through-hole Technology: THT) และชิ้นส่วนชนิดยึดติดพื้นผิว (Surface Mount Technology: SMT/SMD)

## 4.2 ผลการฝึกสอนและประเมินประสิทธิภาพของโมเดลปัญญาประดิษฐ์

การฝึกสอนโมเดลโครงข่ายประสาทเทียมตรวจจับวัตถุ YOLO ได้รับการประเมินประสิทธิภาพผ่านตัวชี้วัดมาตรฐานทางสถิติ ได้แก่ ค่าความสูญเสีย (Loss Function), ความแม่นตรง (Precision: P), ความครอบคลุม (Recall: R), ค่าเฉลี่ยความแม่นตรงเฉลี่ย (Mean Average Precision: mAP) และค่าคะแนนประสิทธิผลฮาร์มอนิก **(F1-Score)**

### 4.2.1 นิยามและหลักการคำนวณค่า F1-Score ในการตรวจสอบ PCB
ในกระบวนการตรวจสอบแผ่นวงจรพิมพ์ ปริมาณชิ้นส่วนอุปกรณ์แต่ละประเภทมีความไม่สมดุลอย่างมาก (Class Imbalance) ตัวอย่างเช่น แผ่นวงจรอาจมีตัวต้านทาน SMD จำนวน 20–30 ตัว แต่มีชิปไอซีเพียง 1–2 ตัว และมีจุดบกพร่อง (Defect) เกิดขึ้นเพียงเล็กน้อย การวัดผลด้วยค่าความถูกต้อง (Accuracy) เพียงอย่างเดียวจึงอาจก่อให้เกิดความคลาดเคลื่อน (Accuracy Paradox) 

ดังนั้น ระบบจึงต้องประเมินผ่านค่า **F1-Score** ซึ่งเป็นค่าเฉลี่ยแบบฮาร์มอนิก (Harmonic Mean) ระหว่าง Precision และ Recall เพื่อชี้วัดว่าโมเดลมีความสมดุลระหว่าง "การไม่ทำนายผิดพลาด (ไม่ทายมั่ว)" กับ "การค้นหาชิ้นส่วนและข้อบกพร่องได้ครบถ้วน (ไม่มองข้าม)" โดยมีสูตรการคำนวณดังนี้

$$\text{Precision (P)} = \frac{TP}{TP + FP}$$

$$\text{Recall (R)} = \frac{TP}{TP + FN}$$

$$\text{F1-Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2TP}{2TP + FP + FN}$$

โดยที่:
- $TP$ (True Positive): การตรวจจับชิ้นส่วนได้ถูกต้องทั้งตำแหน่งและชนิด
- $FP$ (False Positive): การตรวจจับวัตถุผิดพลาด หรือทายสิ่งอื่นเป็นชิ้นส่วนนั้น (นำไปสู่ข้อผิดพลาดแบบทายเกิน)
- $FN$ (False Negative): ชิ้นส่วนมีอยู่จริงบนบอร์ด แต่โมเดลตรวจหาไม่พบ (นำไปสู่การมองข้ามอุปกรณ์)

### 4.2.2 ผลการฝึกสอนและค่า F1-Score สูงสุด (F1-Confidence Analysis)
จากการวิเคราะห์กราฟความสัมพันธ์ระหว่างค่า F1-Score และค่าระดับความเชื่อมั่น (F1-Confidence Curve) ของโมเดล พบว่า:
1. **ช่วงความเชื่อมั่นที่เหมาะสมที่สุด (Optimal Confidence Threshold):** ค่า F1-Score ของโมเดลจะพุ่งขึ้นสูงสุดที่ค่า Confidence ระหว่าง $0.45 - 0.65$ โดยทำค่า **Peak F1-Score สูงสุดได้ถึง 0.9120 (91.20%) ที่ Epoch 53** (Precision = 85.78%, Recall = 97.35%)
2. **การลู่เข้าของโมเดล:** เมื่อการฝึกสอนดำเนินไปจนครบรอบ Loss Function รวมลดลงสู่สภาวะเสถียร โดยมีค่า Classification Loss ต่ำเพียง 0.20 และ Bounding Box Loss ต่ำกว่า 1.00
3. **ผลลัพธ์ในรอบการประเมินสุดท้าย (Final Evaluated Epoch):** โมเดลให้ค่า Precision ที่ 93.98% และ Recall ที่ 86.64% ส่งผลให้ค่า F1-Score ในจุดประเมินปลายทางอยู่ที่ **90.15%** ซึ่งผ่านเกณฑ์ข้อกำหนดของโครงงาน (F1-Score ไม่น้อยกว่าร้อยละ 80) อย่างสมบูรณ์

## 4.3 ผลการทดสอบระบบตรวจสอบความสมบูรณ์ของแผ่น PCB ผ่าน Desktop GUI

โปรแกรมตรวจสอบความสมบูรณ์ของแผ่นวงจรพิมพ์ (Desktop GUI) ทำงานโดยการนำภาพถ่ายที่ตรวจจับผ่านโมเดล YOLO มาเปรียบเทียบกับพิกัดจุดอ้างอิงของแผ่นวงจรต้นแบบ (`Refs.json`) ผ่านอัลกอริทึม **Greedy Nearest-Neighbor Matching** ด้วยระยะห่างแบบยุคลิด (Euclidean Distance: $\sqrt{(x_1-x_2)^2 + (y_1-y_2)^2}$) 

ระบบจะจับคู่อุปกรณ์ที่อยู่ใกล้ที่สุดภายในรัศมี $D_{match}$ และจำแนกผลการตรวจสอบของแต่ละจุดออกเป็น 4 สถานะหลัก ได้แก่:
1. **OK (วงกลมสีเขียว):** ตรวจพบอุปกรณ์ในพิกัดที่ถูกต้อง และชนิดอุปกรณ์ตรงกับจุดอ้างอิง
2. **WRONG (วงกลมสีส้ม/แดง):** ตรวจพบอุปกรณ์ตรงตำแหน่งพิกัด แต่ชนิด/คลาสของอุปกรณ์ไม่ถูกต้อง (เช่น ติดตั้งไอซีผิดเบอร์ หรือสลับชนิดชิ้นส่วน)
3. **MISSING (วงกลมสีแดง):** ไม่พบอุปกรณ์ใดๆ ในตำแหน่งที่ระบุไว้ในจุดอ้างอิง
4. **EXTRA (กรอบสีแดง/ไฮไลท์):** ตรวจพบชิ้นส่วนแปลกปลอมหรืออุปกรณ์เกินขึ้นมาในตำแหน่งที่ไม่มีในจุดอ้างอิง

### 4.3.1 กรณีทดสอบที่ 1: แผ่นวงจรสมบูรณ์ อุปกรณ์ครบถ้วน (Golden Sample - PASS)
ทำการทดสอบกับแผ่นวงจรพิมพ์ที่ผ่านกระบวนการประกอบอย่างสมบูรณ์แบบ 100% มีจำนวนอุปกรณ์อ้างอิงทั้งหมด 47–53 จุด (ประกอบด้วยตัวต้านทาน 20 จุด, ตัวเก็บประจุ 18 จุด, คอนเนคเตอร์ 6 จุด, ไอซี 5 จุด, ไดโอด 2 จุด, คริสตัล 1 จุด, และทรานซิสเตอร์ 1 จุด)
- **ผลการตรวจจับ:** ระบบตรวจพบชิ้นส่วนครบทุกตำแหน่ง และจับคู่พิกัดตรงกันทุกจุด
- **การตัดสินสถานะ:** แสดงวงกลมสีเขียว (OK) ครบทุกตำแหน่ง จำนวน Missing = 0, Wrong = 0, Extra = 0
- **คำตัดสินภาพรวม:** **PASS (All expected components matched)**
- **ความแม่นยำ:** ตรวจสอบซ้ำ 30 ครั้ง ให้ผลตัดสินเป็น PASS ถูกต้อง 100%

### 4.3.2 กรณีทดสอบที่ 2: แผ่นวงจรมีอุปกรณ์ขาดหาย (Defect: MISSING)
ทำการจำลองสถานการณ์โดยการถอดชิ้นส่วนอุปกรณ์ออกจากแผ่นวงจรพิมพ์จริงในตำแหน่งสำคัญ เช่น ถอดตัวเก็บประจุ (Capacitor) และคอนเนคเตอร์ (Connector) ออก
- **ผลการตรวจจับ:** โมเดลไม่ตรวจพบบ็อกซ์ในบริเวณที่ชิ้นส่วนถูกถอดออก อัลกอริทึม Nearest-Neighbor ค้นหาไม่พบ Detection ภายในรัศมี $D_{match}$
- **การตัดสินสถานะ:** ระบบมาร์กจุดอ้างอิงดังกล่าวเป็นวงกลมสีแดงพร้อมข้อความระบุ `Capacitor MISS`
- **คำตัดสินภาพรวม:** **FAIL (Missing: 2)**

### 4.3.3 กรณีทดสอบที่ 3: แผ่นวงจรมีการติดตั้งอุปกรณ์ผิดประเภท (Defect: WRONG)
ทำการทดสอบกรณีติดตั้งชิ้นส่วนผิดประเภท ณ ตำแหน่งเดิม (เช่น วางทรานซิสเตอร์ในตำแหน่งที่ควรเป็นไอซี)
- **ผลการตรวจจับ:** โมเดลตรวจพบวัตถุ ณ พิกัดดังกล่าวด้วยระยะห่าง $D \le D_{match}$ แต่ค่า Label ไม่ตรงกัน (`det['label'] != ref['label']`)
- **การตัดสินสถานะ:** ระบบเปลี่ยนการแสดงผลเป็นสถานะ **WRONG** (แสดงข้อความเปรียบเทียบ เช่น `IC != transistor`)
- **จุดเด่นเหนือกว่าระบบรุ่นพี่:** จุดนี้เป็นข้อแตกต่างสำคัญที่ระบบของเราเหนือกว่าระบบการนับจำนวนของรุ่นพี่ เนื่องจากระบบของรุ่นพี่จะนับจำนวนชิ้นส่วนรวมและไม่สามารถตรวจพบการใส่ชิ้นส่วนผิดประเภทที่พิกัดเดิมได้

### 4.3.4 กรณีทดสอบที่ 4: มีสิ่งแปลกปลอมหรือชิ้นส่วนติดตั้งเกิน (Defect: EXTRA)
ทำการทดสอบโดยวางชิ้นส่วนเพิ่มเติมลงบนพื้นที่ว่างของแผ่นวงจรพิมพ์
- **ผลการตรวจจับ:** โมเดลตรวจจับวัตถุได้ แต่เมื่อจับคู่กับ `Refs.json` แล้ว วัตถุชิ้นนี้เหลืออยู่ในเซ็ต `unmatched_det_indexes`
- **การตัดสินสถานะ:** ระบบจัดเป็นสถานะ **EXTRA** ตีกรอบสีแดงเตือนบนภาพ และตัดสินผลรวมเป็น **FAIL (Extra: 1)**

### 4.3.5 ผลการประเมินค่า F1-Score และความแม่นยำของการตัดสินผลการตรวจสอบ (Inspection Verdict Performance)
จากการทดสอบระบบจริงอย่างต่อเนื่องและบันทึกประวัติลงในไฟล์ฐานข้อมูล `inspection_log.csv` (สถิติทดสอบสะสมกว่า 1,400 ครั้ง) ได้ทำการสุ่มชุดตัวอย่างแผ่นวงจรพิมพ์จริงจำนวน **200 บอร์ดควบคุม** โดยแบ่งเป็นแผ่นสมบูรณ์ (Normal) จำนวน 50 บอร์ด และแผ่นที่มีข้อบกพร่อง (Defective: Missing/Wrong/Extra) จำนวน 150 บอร์ด เพื่อนำมาคำนวณ Confusion Matrix ในระดับการตัดสินผลของระบบ (Inspection-Level Evaluation) ดังแสดงในตารางที่ 4.4

**ตารางที่ 4.4** เมทริกซ์ความสับสน (Confusion Matrix) ในการตัดสินผลแผ่นวงจรพิมพ์ (ชุดทดสอบ 200 บอร์ด)

| ผลการตรวจสอบจริง (Ground Truth) | ผลการทำนายของระบบ: ตรวจพบข้อบกพร่อง (Predicted Defect / FAIL) | ผลการทำนายของระบบ: ผ่านเกณฑ์สมบูรณ์ (Predicted Normal / PASS) | รวมจำนวนบอร์ดจริง |
| :--- | :---: | :---: | :---: |
| **แผ่นวงจรมีข้อบกพร่องจริง (Defective)** | **$TP = 143$** (ตรวจพบของเสียถูกต้อง) | **$FN = 7$** (ของเสียหลุดรอด / False Accept) | 150 |
| **แผ่นวงจรสมบูรณ์จริง (Normal)** | **$FP = 2$** (ของดีแจ้งเตือนผิด / False Reject) | **$TN = 48$** (ของดีผ่านเกณฑ์ถูกต้อง) | 50 |
| **รวมจำนวนบอร์ดที่ทำนาย** | 145 | 55 | **200** |

จากตาราง Confusion Matrix สามารถคำนวณตัวชี้วัดประสิทธิภาพเชิงระบบได้ดังนี้:

1. **ความแม่นตรงในการตรวจจับของเสีย (Defect Precision):**
   $$\text{Precision} = \frac{TP}{TP + FP} = \frac{143}{143 + 2} = \frac{143}{145} = \mathbf{98.62\%}$$
   *(สะท้อนว่าเมื่อระบบแจ้งเตือนว่าบอร์ดมีข้อบกพร่อง/FAIL จะมีความถูกต้องและน่าเชื่อถือสูงถึง 98.62%)*

2. **ความครอบคลุมในการคัดแยกของเสีย (Defect Recall / Sensitivity):**
   $$\text{Recall} = \frac{TP}{TP + FN} = \frac{143}{143 + 7} = \frac{143}{150} = \mathbf{95.33\%}$$
   *(สะท้อนว่าระบบสามารถดักจับแผ่นวงจรที่มีข้อบกพร่องหลุดรอดได้ถึง 95.33%)*

3. **ค่าคะแนนประสิทธิผลของระบบตรวจสอบ (Inspection F1-Score):**
   $$\text{F1-Score} = 2 \times \frac{0.9862 \times 0.9533}{0.9862 + 0.9533} = \frac{1.8804}{1.9395} = \mathbf{96.95\%}$$

4. **ความถูกต้องรวมของระบบ (Overall System Accuracy):**
   $$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} = \frac{143 + 48}{200} = \frac{191}{200} = \mathbf{95.50\%}$$

5. **อัตราความผิดพลาดรวม (Total Error Rate):**
   $$\text{Error Rate} = 1 - \text{Accuracy} = \frac{2 + 7}{200} = \mathbf{4.50\%}$$

**ตารางที่ 4.5** สรุปเปรียบเทียบผลลัพธ์ที่ได้กับเกณฑ์ขอบเขตโครงงานที่ตั้งไว้ในบทที่ 1

| ดัชนีชี้วัดประสิทธิภาพ (Metrics) | เกณฑ์เป้าหมายในขอบเขต (Chapter 1) | ค่าที่ทำได้จริงในการทดลอง | สถานะการประเมิน |
| :--- | :---: | :---: | :---: |
| **โมเดล AI: F1-Score รวมทุกคลาส** | ไม่น้อยกว่า 80.00% | **90.15%** (Peak 91.20%) | **ผ่านเกณฑ์ (สูงกว่าเป้าหมาย +10.15%)** |
| **โมเดล AI: Mean Average Precision (mAP@50)** | - | **91.90%** | **มีประสิทธิภาพสูงมาก** |
| **ระบบตรวจสอบ: ความถูกต้องรวม (Accuracy)** | ไม่น้อยกว่า 90.00% | **95.50%** | **ผ่านเกณฑ์ (สูงกว่าเป้าหมาย +5.50%)** |

## 4.4 ผลการทดสอบระบบเว็บแอปพลิเคชันและการสแกนอัตโนมัติ (Web-based AOI System)

ระบบตรวจสอบบนเว็บ (Web Edition) พัฒนาขึ้นด้วยสถาปัตยกรรม Decoupled Full-stack ประกอบด้วย Frontend ที่พัฒนาด้วย Next.js/TypeScript และ Backend พัฒนาด้วย FastAPI ซึ่งควบคุมการทำงานร่วมกับระบบขับเคลื่อนกลไกแกน XY (Arduino Nano Protocol v2)

### 4.4.1 ผลการทดสอบการสแกนอัตโนมัติ (Serpentine Raster Scan)
ระบบสแกนอัตโนมัติถูกออกแบบให้กล้องเคลื่อนที่เหนือแผ่น PCB ในแนวระนาบ XY แบบฟันปลา (Serpentine Pattern) เพื่อถ่ายภาพทีละช่องตาราง (Field of View: FOV) และส่งภาพเข้าสู่ไปป์ไลน์วิเคราะห์ผล:
1. **การควบคุมการสั่นสะเทือนและการเคลื่อนที่:** ใช้ขั้นตอน `Move → Settle → Capture` โดยกำหนดระยะเวลาหน่วงการหยุดนิ่ง (Settle Time) 150–200 ms ก่อนสั่งเปิดชัตเตอร์กล้อง เพื่อป้องกันอาการภาพเบลอจากการเคลื่อนไหว (Motion Blur)
2. **การรับประกันภาพสดใหม่ (Fresh Frame Guarantee):** ฟังก์ชัน `get_fresh_frame(after_timestamp)` ใน Backend ประสบความสำเร็จในการป้องกันปัญหากล้องนำภาพจากแคชเฟรมเดิมก่อนการเคลื่อนที่มาวิเคราะห์ ทำให้ผลการตรวจจับในทุกพิกัดตำแหน่งถูกต้อง 100%

### 4.4.2 ผลการทดสอบระบบความปลอดภัยและสิทธิ์การควบคุม (Control Lease & Safety)
1. **ระบบบริหารจัดการสิทธิ์ (Control Lease):** ป้องกันการแย่งคำสั่งควบคุมเมื่อเปิดหลายหน้าต่าง โดยผู้ควบคุม (Operator) ถือสิทธิ์ควบคุมมอเตอร์เพียงอุปกรณ์เดียว อุปกรณ์อื่นจะแสดงผลในโหมด Viewer เพื่อความปลอดภัย
2. **ปุ่มหยุดฉุกเฉิน (Emergency STOP):** ทดสอบการกดปุ่ม STOP ขณะที่ระบบกำลังสแกน พบว่าระบบส่งสัญญาณขัดจังหวะ (Preempt) ล้างคิวคำสั่งการเคลื่อนที่และหยุดมอเตอร์ได้ภายในเวลาไม่เกิน 50 ms ทันที

### 4.4.3 ผลการรันชุดทดสอบอัตโนมัติของระบบซอฟต์แวร์ (Automated Test Suite)
**ตารางที่ 4.6** สรุปผลการรันชุดทดสอบความถูกต้องของซอฟต์แวร์ระบบตรวจสอบ

| ชุดการทดสอบ (Test Suite) | ขอบเขตการทดสอบ | จำนวนกรณีทดสอบ | ผลการทดสอบ | เวลาที่ใช้ |
| :--- | :--- | :---: | :---: | :---: |
| **Backend API & Logic (Pytest)** | การตัดสิน PASS/FAIL, การเคลื่อนที่แกน XY, สิทธิ์ Lease, API Health | 14 ข้อ | **ผ่าน 100% (Passed)** | 1.26 วินาที |
| **Frontend Web Build (Next.js)** | การคอมไพล์ TypeScript, ความถูกต้องของหน้า UI ทั้ง 5 หน้า | 4 หน้าสถิติ | **ผ่าน 100% (Compiled)** | 2.70 วินาที |

## 4.5 ผลการทดสอบและวิเคราะห์ประสิทธิภาพของระบบแสงสว่างแบบโดมกระจายแสง (Diffuse Dome Light)

หนึ่งในอุปสรรคสำคัญที่ระบุไว้ในงานวิจัยก่อนหน้า (โครงงานของรุ่นพี่ ปี 2568) คือปัญหาเรื่อง **แสงสะท้อนบนแผงวงจรพิมพ์และจุดบัดกรี (Specular Reflection and Glare)** ซึ่งทำให้โมเดลเกิดความสับสนระหว่างรอยบัดกรีที่มีแสงสะท้อนจ้า กับขาชิ้นส่วนอุปกรณ์อิเล็กทรอนิกส์

ในการดำเนินโครงงานนี้ จึงได้ออกแบบและสร้างชุดไฟตรวจ PCB ทรงครึ่งวงรีแบบกระจายแสง (Diffuse Dome Light R1) ด้วย OpenSCAD โดยใช้แถบหลอด LED อุณหภูมิสี 4000–5000K ขับด้วยแรงดัน 24V ติดตั้งรอบขอบฐานและยิงแสงสะท้อนขึ้นสู่ผิวด้านในของโดมสีขาวด้าน เพื่อให้แสงสะท้อนกระจายตัวลงสู่แผ่น PCB อย่างนุ่มนวลและสม่ำเสมอทุกทิศทาง

### 4.5.1 การเปรียบเทียบเชิงคุณภาพของภาพถ่าย
1. **การกำจัดจุดสะท้อนจ้า (Hotspots Elimination):** แสงจากโดมกระจายแสงสามารถขจัดจุดขาวจ้าบนหลังตัวถังชิป IC และหยดตะกั่วบัดกรีได้อย่างสมบูรณ์ ทำให้มองเห็นตัวอักษร Silkscreen และมาร์กเกอร์บนตัวถังอุปกรณ์ได้อย่างคมชัด
2. **การลดเงาตกกระทบ (Shadow Reduction):** ชิ้นส่วน Through-hole ที่มีความสูง จะไม่ทอดเงามืดบดบังชิ้นส่วน SMD ขนาดเล็กที่ติดตั้งอยู่ข้างเคียง
3. **ความสม่ำเสมอของความสว่าง:** ผลการวัดค่าความสว่างทั่วพื้นที่ตรวจสอบขนาด 160 × 120 mm พบว่าความเบี่ยงเบนของความสว่างใน 9 จุดทดสอบมีค่าแตกต่างกันไม่เกิน $\pm 8.5\%$ ผ่านเกณฑ์มาตรฐาน Machine Vision

### 4.5.2 ผลกระทบเชิงปริมาณและค่า F1-Score ภายใต้ระบบแสงสว่าง
**ตารางที่ 4.7** ผลการเปรียบเทียบตัวชี้วัดประสิทธิภาพและค่า F1-Score ระหว่างสภาพแสงทั่วไปกับระบบไฟ Diffuse Dome Light

| ดัชนีชี้วัดประสิทธิภาพ | แสงสว่างทั่วไปในห้อง (Ambient / Direct Light) | ระบบไฟแบบโดมกระจายแสง (Diffuse Dome Light R1) | การเปลี่ยนแปลงเชิงพัฒนา |
| :--- | :---: | :---: | :---: |
| **Precision รวม** | 84.20% | **93.98%** | **เพิ่มขึ้น +9.78%** |
| **Recall รวม** | 78.50% | **86.64%** | **เพิ่มขึ้น +8.14%** |
| **F1-Score รวมของโมเดล** | **81.25%** | **90.15%** | **เพิ่มขึ้น +8.90%** |
| **อัตราการตรวจจับผิดพลาด (False Positive)** | 15.80% | **6.02%** | **ลดลง -9.78%** |
| **อัตราการมองข้ามชิ้นส่วน (False Negative)** | 21.50% | **13.36%** | **ลดลง -8.14%** |
| **F1-Score ของชิ้นส่วน SMD (`sot`/`resistor`)** | 77.20% | **87.55%** | **เพิ่มขึ้น +10.35%** |

ผลการทดลองยืนยันอย่างชัดเจนว่า **การนำชุดไฟ Diffuse Dome Light มาใช้งานร่วมกับระบบปัญญาประดิษฐ์ สามารถยกระดับค่า F1-Score รวมของระบบขึ้นถึง 90.15% (เพิ่มขึ้น +8.90%) และเพิ่ม F1-Score ของชิ้นส่วน SMD ขนาดเล็กได้ถึง +10.35%** ซึ่งพิสูจน์ได้ว่าการออกแบบระบบแสงเชิงวิศวกรรมมีผลโดยตรงต่อการยกระดับประสิทธิภาพของโมเดล AI ในการตรวจสอบแผ่นวงจรพิมพ์จริงในสายการผลิต
